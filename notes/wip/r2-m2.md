## Measurements
- ep1 hub chaos, single runs (noisy: the route differs run to run): off 148 fps (1% 79.7); hybrid world-only + clip
  205.8 fps (GPU 4.87, front 3.94, GS 2.88, worker 3.15 ms).
- GPU replay (ep1 light, 40 VBlanks, 3x): exact world ff-tri-fast-z 0.65 -> hybrid 0.21 + r2 0.44: R2's per-pixel cost
  equals the exact path's. Knobs (PS2_R2_DBG): no texture 0.44, raster Z 0.43, float VS 0.45, constant PS 0.25 (fill /
  raster bound), unconsolidated 0.46. Draw count was not R2's GPU cost; fill is.
- 1 Hz ~18 ms frame spike in both modes (instrumentation or game?).
- 30-50 ms hitches every ~0.2 s in GPU-bound stretches (props made ep1 GPU-bound: 220-280 fps): the driver blocked the
  render thread inside whichever D3D call hit its queue limit (R2's per-segment cbuffer Map/UpdateSubresource 2-13 ms,
  the exact path's arena Map 12 ms; PS2_GS_HW_STATS=2 slow frames: render wall 45-56 ms, CPU 0.4). Fixes: segment
  constants now a record in fdata (gpu_r2_seg; draw ids = record offset / 32 via StartInstanceLocation; static cbuffer
  written once), GPU frame fence in gpu_exec.c (event query per frame, wait for frame N-2 before recording frame N;
  PS2_GPU_FENCE=n, 0 off). Being measured (r2m2_c9: ref / modern / modern without fence).
