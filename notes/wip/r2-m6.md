## Done
- Base exe: build\base\sly2_base.exe (main, release). Diagnostic exe build\base\sly2_diag.exe (+ PS2_R2_DROPCLS=<mask>:
  drop the render-list entries of those render classes; r2_capture.c).
- Profile, m2_boardroom modern 3x (PS2_GPU_PROF=1, prof_window over the chaos window): GPU 5.33 ms = ff-tri-fast-z 2.72,
  ref-tri 0.85, r2 0.45, ref-other 0.30, alias16-draw 0.26, present 0.21, clear 0.15, ff-line 0.13. PROF_OPS frame 22000:
  ONE additive FF draw (564 triangles over the whole screen, alpha 48, Z GREATER + write, ATST split) = 1.29 ms: the steam
  over the pool. PS2_R2_DROPCLS=4 (class 2 = particles dropped): GPU 5.33 -> 4.23 ms, fps 175 -> 215 (with PROF on);
  the steam / splashes vanish. m1_brawl: GPU 3.38 -> 2.81, fps 255 -> 298. (build\prof\drop.log: the other scenes.)
- Conclusion: the particles' cost is GPU fill of their exact FF triangles (per fragment: record loads, 7 attribute steps,
  64-bit Z, conservative depth out); their VU1 simulation runs on the CPU worker (recompiled VU, ~1 ms stage, not the
  limit). So R6 = the particles' triangles (the VU's own vertices) through a native pipeline, not a compute port of the VU
  physics (that would cut nothing on the GPU).
- Code (compiles, untested): R2H_PART hints (r2.h; r2_capture.c part_hint: class-2 span begin / end, hybrid + bracket,
  PS2_R2_PART=0 off), gpu_r2front.c gf_r2_part (reset per VBlank) + stats, gpu_front.c "part" prims (FF tri, ff_fast,
  fx_on, vram texture, no LOD/DATE/dither, 32-bit) -> own draws, GPU_DF_PART, vertices carry their Z (emit_vertex nb < 0);
  gpu_exec.c part_exec() -> vs_ff_part + ps_ff_p{0,1}{,d} (gs.hlsl PART: hardware-interpolated colour / fog / S/T/Q / Z,
  ff_out shared with ps_ff), prof category "part", PS2_GPU_PART=0 executor off, PS2_GPU_AB toggles it.
